# ATS Resume Scorer

AI-powered resume analyser: upload a resume (PDF/DOCX), optionally add a job description, and get an ATS score out of 100, prioritised feedback, skill validation, and a downloadable PDF report.

- **Live frontend:** https://atsscorer-vraj.streamlit.app
- **Full project write-up:** [docs/Project_Overview.md](docs/Project_Overview.md)

> **Note:** the hosted backend (Render) is currently offline, so the analysis features need the backend running locally. See [Running locally](#running-locally) below.

---

## How the app is split

| Part | Tech | Where it runs |
|---|---|---|
| Frontend | Streamlit | Streamlit Cloud (hosted) or `localhost:8501` |
| Backend API | FastAPI | `localhost:8000` (Render currently offline) |
| Auth + database | Supabase | Hosted by Supabase |
| LLM parsing | Groq API | Hosted by Groq |

The frontend talks to the backend over HTTP. The hosted Streamlit app **cannot reach a backend on your `localhost`**, so to use the full app today, run **both** the backend and the frontend locally.

## Prerequisites

- **Python 3.12 or newer** (the backend uses f-string syntax that older versions reject)
- A **Supabase** project (for sign-in and history)
- A **Groq API key** ([console.groq.com](https://console.groq.com))
- System libraries used by PDF export and file-type detection:

  **macOS**
  ```bash
  brew install libmagic pango cairo gdk-pixbuf libffi
  ```
  **Ubuntu / Debian**
  ```bash
  sudo apt install -y libmagic1 libcairo2 libpango-1.0-0 libpangoft2-1.0-0 libffi-dev
  ```
  **Windows:** use WSL, or install `python-magic-bin` and the WeasyPrint GTK runtime.

## Running locally

All commands are run from the **project root** (`ATS_SCORER/`).

### 1. Clone and create a virtual environment

```bash
git clone https://github.com/vrajshah2706/ATS_SCORER.git
cd ATS_SCORER

python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
```

### 2. Install dependencies

```bash
pip install -r requirements.txt
python -m spacy download en_core_web_md
```

### 3. Configure environment variables

**Backend**: create `backend/.env`:

```env
SUPABASE_URL=https://<your-project>.supabase.co
SUPABASE_KEY=<service_role key>          # server-side only, never expose
SUPABASE_ANON_KEY=<anon public key>
SUPABASE_JWT_SECRET=<JWT secret>         # only needed for HS256 projects; optional if your project uses JWKS
GROQ_API_KEY=<your groq key>
```

**Frontend**: create a `.env` file in the project root:

```env
SUPABASE_URL=https://<your-project>.supabase.co
SUPABASE_ANON_KEY=<anon public key>
```

(Alternatively, put these under a `[supabase]` section in `.streamlit/secrets.toml`.)

Both files are git-ignored. Never commit keys.

### 4. Set up the Supabase table

In the Supabase SQL editor, create the table the backend writes to:

```sql
create table public.analyses (
  id               bigint generated by default as identity primary key,
  user_id          uuid not null,
  filename         text not null,
  ats_score        numeric,
  keyword_match    numeric,
  missing_keywords jsonb default '[]'::jsonb,
  analysis_result  jsonb not null,
  created_at       timestamptz default now()
);
```

Also make sure **Email** sign-in is enabled under Authentication → Providers. If email confirmation is on, new users must confirm their email before signing in.

### 5. Provide the sentence-transformer model

The backend loads the fine-tuned model from `backend/core/models/fine_tuned_model/`. The repo contains only the config and tokenizer files there; the **weights file** (`model.safetensors`, about 400+ MB) is too large for a normal GitHub commit, so it has to be added locally:

1. Download the zip produced at the end of `JupyterNotebook/BERT_FINETUNE.ipynb` (`my_finetuned_model.zip`) from Colab and unzip it.
2. Copy the **files inside** the unzipped folder into `backend/core/models/fine_tuned_model/`, replacing the existing files. Do not copy the outer folder itself, or you will end up with `fine_tuned_model/my_finetuned_model/...`.
3. Confirm `model.safetensors` is now in `backend/core/models/fine_tuned_model/` next to `config.json`.

If you don't have the weights, you can run on the base model instead by adding this line to `backend/.env`:

```env
SENTENCE_TRANSFORMER_MODEL=all-mpnet-base-v2
```

It downloads automatically on first start. Scores will still work, but without the fine-tuning improvements.

### 6. Start the backend

```bash
uvicorn backend.main:app --reload
```

The first start is slow because the spaCy and sentence-transformer models are loaded once at startup. When you see `All models loaded`, check:

- Health check: http://localhost:8000/api/v1/health
- Interactive API docs: http://localhost:8000/docs

### 7. Start the frontend (in a second terminal)

```bash
source venv/bin/activate
streamlit run frontend/streamlit_app.py
```

Open http://localhost:8501. The frontend defaults to `http://localhost:8000` for the backend, so no extra config is needed locally.

### 8. Use it

1. Create an account or sign in from the sidebar.
2. Open **ATS Scorer**, upload a PDF or DOCX (max 5 MB).
3. Choose **General ATS Score**, or **Job Description Comparison** and paste a job description.
4. Click **Analyze Resume** (takes roughly 10–30 seconds).
5. Download the PDF report, or revisit past results under **History**.

## Pointing the frontend at a different backend

By default the frontend calls `http://localhost:8000`. Once the backend is hosted again, add this to the Streamlit secrets (Streamlit Cloud: *App settings → Secrets*; locally: `.streamlit/secrets.toml`):

```toml
[backend]
url = "https://<your-backend-url>"

[supabase]
SUPABASE_URL = "https://<your-project>.supabase.co"
SUPABASE_ANON_KEY = "<anon public key>"
```

And add the frontend's URL to `ALLOWED_ORIGINS` in `backend/core/config.py`.

## Troubleshooting

| Problem | Likely cause / fix |
|---|---|
| `Could not reach the backend` in the UI | The backend isn't running. Start it with `uvicorn backend.main:app --reload` and keep it running |
| Hosted Streamlit app shows the same error | Expected while the backend is offline: the hosted app can't see your `localhost` |
| Backend crashes on startup loading the model | Weights missing from `fine_tuned_model/`. See step 5 |
| `OSError: [E050] Can't find model 'en_core_web_md'` | Run `python -m spacy download en_core_web_md` (the app falls back to `en_core_web_sm` if installed) |
| `ImportError: failed to find libmagic` | Install `libmagic` (see Prerequisites) |
| PDF report fails / WeasyPrint errors | Install the Cairo/Pango libraries (see Prerequisites) |
| `SyntaxError` in f-strings on startup | Python is older than 3.12. Recreate the venv with 3.12+ |
| `401` errors | Not signed in, token expired (sign in again), or Supabase keys in `backend/.env` are wrong |
| `Auth not configured on the server` | Set `SUPABASE_URL` (and/or `SUPABASE_JWT_SECRET`) in `backend/.env` |
